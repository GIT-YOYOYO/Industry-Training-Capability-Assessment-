# 设计文档

## 0. 一句话

对每一位即将参加职业培训的学员，在培训开始前用 5 个维度的基线测评（x1–x5）预测其培训后
是否“能力不达标”，用于名额有限的强化辅导班筛选（取风险最高的 10%）。

## 1. 五个问题

### 1.1 为什么做

强化辅导班名额有限，如果平均分配或凭经验挑人，有限的辅导资源会落到本不需要的人身上。
如果能提前识别高风险学员，就能把名额用在最该辅导的人身上，提升整体达标率。

### 1.2 做什么

二分类：预测“培训后能力不达标”（`low_ability = 1`）。输入是培训前的 5 个基线维度，
输出是一个风险概率、一个是否进入强化班的决策、以及这个决策的解释。

### 1.3 怎么做

数据准备（清洗 → 按中心分组切分 → 训练集上定标签阈值）→ 训练（两个基线 + 逻辑回归 + LightGBM，
同口径对比）→ 评估（PR-AUC 为主，含自助区间、切片、校准、错误分析）→ 解释（可加性 SHAP）→
模型包 → 推理（预测 + 决策 + 解释）→ 质量门。

### 1.4 做到什么程度（含“不做什么”）

做到：可复现（一条命令重跑、指纹核对）、可解释（每条预测给基准值与贡献）、有门禁（不过即报错）。

**不做什么：**

1. **不预测“培训后每个学员的具体分数曲线”**——只做“是否不达标”的二分类，不做回归或时序预测。
2. **不把机构类型 `schooltype` 放进模型**——避免按机构类型系统性差别对待（见 ADR-002）。
3. **不做线上服务与主动学习闭环**——本期只交付离线模型包与推理入口，不部署 API、不做回流。
4. **不用深度学习或复杂集成堆分数**——5 个线性相关的基线维度，复杂模型没有增益（实测 LightGBM 未超过逻辑回归）。

### 1.5 怎么验证

- `uv run python scripts/ci.py` 全绿；
- 训练门禁三条：主指标比基线高 ≥0.05、切片 ROC-AUC 差距 ≤0.20、解释可加回（误差 ≤1e-4）；
- 破坏实验：改坏一处关键代码，质量门变红（见 `docs/self-assessment.md`）。

## 2. 四个口径

### 2.1 样本

一名学员一条记录（`stuid` 唯一，32,165 条）。`y/y1..y5` 整行缺失的 10 条记录剔除，
清洗后 32,155 条，来自 160 个培训中心。删除多少、缺了哪些列，都记在 `manifest.json.cleaning`。

### 2.2 标签

`low_ability = 1` 当且仅当培训后综合能力 `y <= 训练集 y 的 25% 分位`（阈值 = -0.6265）。
阈值**只在训练集上计算**，验证集和测试集复用同一阈值，不看它们的分布。业务含义：
“后四分之一”定义为“不达标”，约 25% 的学员为正例。

### 2.3 时点与切分

- 预测发生在**培训开始前**：只允许用培训前就能拿到的信息（x1–x5 基线测评）。
- `x` 是 x1–x5 的确定性线性组合，`y1–y5` 是目标的成分，都不能进特征（见 2.4 与 ADR）。
- 切分：按培训中心 `schoolid` **分组**切分，train/val/test 的中心互不相交
  （train 104 中心 / val 24 中心 / test 32 中心）。理由：基线能力 `x` 的 ICC≈0.815、
  结果 `y` 的 ICC≈0.585，同一中心学员高度相似；随机切分会让同中心学员跨训练/测试，严重高估泛化。
  分组切分后测试集是“没见过的中心”，更接近真实上线。

### 2.4 决策

名额制（Top-K）：每批取风险分数最高的 `k_fraction = 10%` 进入强化班。
- 离线评估按批内 Top-K 执行（名额固定），测试集选中比例 10.0%、召回 30.4%、精确率 84.3%。
- 单条/小批量推理没有“批次”语境，用验证集等效阈值（0.9663）判定，随模型包一起保存。

## 3. 主指标与基线

- **主指标：PR-AUC（average precision）**。正例约 25%，且决策是名额制（只看头部排序），
  PR-AUC 比 ROC-AUC 更关注“最该辅导的人有没有排前面”。
- 辅助指标：ROC-AUC、Top-K 召回/精确率、Brier、ECE。
- **朴素基线**：`DummyClassifier(prior)` 的 PR-AUC = 正例率（验证集 0.2654）；规则打分
  （x1–x5 等权平均的负值）PR-AUC = 0.6788。逻辑回归 0.6811，LightGBM 0.6767。
- 结论：**信号近似线性**，复杂模型无增益；诚实记录，不硬吹模型。

## 4. 特征契约

见 `configs/features.yaml`。入模：x1–x5。禁用及理由：

| 列 | 理由 |
|---|---|
| `x` | x1–x5 的确定性线性组合（R²≈0.99999999），入模只引入共线性与冗余 |
| `y1–y5` | 目标 `y` 的成分（y 是它们的线性组合），目标泄漏 |
| `y` | 标签来源列 |
| `stuid` / `schoolid` | 标识符；分组切分下测试集的中心训练时不可见 |
| `schooltype` | 机构类型，为避免按机构系统性差别对待，未入模 |

`tests/acceptance/test_feature_contract.py` 守着“禁用列绝不进特征、每条禁用都有理由”。

## 5. 解释

- 逻辑回归：贡献_j = coef_j × 标准化后取值，基准值 = 截距（标准化后训练均值=0，即“平均学员”）。
- LightGBM：`pred_contrib=True` 的 TreeSHAP，最后一列为基准值。
- 统一约定：**基准值 + 全部贡献 = 模型原始输出（对数几率）**，单位写清，不把对数几率当概率加减。
  `tests/unit/test_explain.py` 对两个模型都验证加和。

## 6. 局限与风险

- **切片差距接近门槛**：按机构类型切片时 `schooltype=0` 组（n=173、正例率 4.6%）ROC-AUC 0.73，
  与最佳组差 0.178，逼近 0.20 门槛。该组样本少，上线后应重点监控其漏报。
- **PR-AUC 不可跨组比**：不同组正例率差异极大（1.5%~62%），PR-AUC 绝对值随正例率变化，
  跨组比较只看 ROC-AUC 或 lift（见 `reports/evaluation.md` 与 ADR-005）。
- **未做线上回流**：没有真实线上数据，效果用“未来”切片模拟，实际部署后需用标签成熟的数据复核。
- **阈值与名额**：单条推理用验证集等效阈值，跨分布会有选中比例漂移；批量部署建议按批 Top-K。
